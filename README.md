# Торговый бот для BingX (спот и фьючерсы)

Автоматический торговый бот на Python. Он анализирует рынок по техническим индикаторам и сам открывает и закрывает сделки на бирже **BingX** через API-ключи.

**Возможности:**

- **Два рынка:** спот (`spot`) и бессрочные USDT-фьючерсы (`swap`) с плечом, лонгами и шортами.
- **Две стратегии:**
  - `mean_reversion` — возврат к среднему (Bollinger Bands + RSI + фильтр ADX);
  - `voting` — голосование шести индикаторов (EMA, EMA200, MACD, RSI, Bollinger, OBV).
- **Риск-менеджмент:**
  - размер позиции считается от риска на сделку;
  - стоп-лосс и тейк-профит по ATR, трейлинг-стоп;
  - дневной лимит убытка, лимит одновременных позиций, пауза после сделки;
  - на фьючерсах стоп-лосс дублируется ордером на бирже.
- **Бэктест** на истории с отчётом: доходность, просадка, Шарп, win rate, profit factor.
- **Paper trading** — работа на живых ценах без реальных ордеров.
- **Уведомления в Telegram** о сделках, ошибках и итогах дня.
- **Сохранение состояния:** после перезапуска бот подхватывает открытые позиции.

## Однофайловая версия

Весь бот также собран в один файл — **`trading_bot.py`** (~1750 строк). Он работает так же, как пакет `bot/`, но настройки задаются прямо в блоке `SETTINGS` в начале файла:

```bash
pip install ccxt pandas numpy requests python-dotenv pyyaml
python trading_bot.py backtest --days 180
python trading_bot.py run
```

Ключи по-прежнему лежат в файле `.env` рядом со скриптом. Можно использовать и YAML-конфиг: `python trading_bot.py -c config.yaml run`. Все команды из этой инструкции работают, если заменить `python -m bot` на `python trading_bot.py`.

> ⚠️ **Важно.** Торговля криптовалютой, особенно с плечом, связана с высоким риском потери средств. Ни одна стратегия не гарантирует прибыль, а хороший бэктест не гарантирует хороших результатов в будущем. Бот предоставляется «как есть». Начинайте с бэктеста, потом поработайте в режиме `paper`, а в `live` запускайте только с суммой, потерю которой готовы перенести.

## 1. Установка

Нужен **Python 3.10 или новее**.

```bash
git clone <адрес-репозитория> trading-bot
cd trading-bot

python3 -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate

pip install -r requirements.txt
# Необязательно: графики в бэктесте и тесты
pip install -r requirements-dev.txt

cp config.example.yaml config.yaml # Windows: copy config.example.yaml config.yaml
cp .env.example .env               # Windows: copy .env.example .env
```

Проверьте, что всё работает (запустятся тесты, сеть не нужна):

```bash
python -m pytest -q
```

## 2. API-ключи BingX

Для режимов `paper` и `backtest` ключи **не нужны**: используются только публичные котировки. Ключи нужны только для `live`.

1. Войдите на bingx.com, откройте **Профиль → API Management** и создайте API-ключ.
2. Права ключа:
   - ✅ **Read** (чтение);
   - ✅ **Spot Trading** — если торгуете на споте;
   - ✅ **Perpetual Futures Trading** — если торгуете фьючерсами;
   - ❌ **Withdraw (вывод средств) — никогда не включайте!**
3. **Обязательно привяжите ключ к IP-адресу** (IP whitelist) того компьютера или сервера, где работает бот. Тогда украденный ключ не сработает с чужого IP. Свой внешний IP можно узнать командой `curl ifconfig.me`.
4. Впишите ключи в файл `.env`:

   ```
   BINGX_API_KEY=ваш_api_key
   BINGX_API_SECRET=ваш_secret_key
   ```

Файл `.env` добавлен в `.gitignore` и не попадёт в git. Никому не передавайте ключи и не публикуйте их.

Для фьючерсов переведите на USDT-фьючерсный счёт BingX средства, которыми будет торговать бот. Для спота держите их на спотовом счёте.

## 3. Настройка config.yaml

Все параметры подробно прокомментированы в `config.example.yaml`. Главные из них:

| Параметр | Что значит |
|---|---|
| `mode` | `paper` — симуляция, `live` — реальная торговля |
| `exchange.market_type` | `spot` — спот; `swap` — бессрочные фьючерсы |
| `symbols` | пары. Спот: `BTC/USDT`; фьючерсы: `BTC/USDT:USDT` |
| `timeframe` | таймфрейм свечей: `5m`, `15m`, `1h`, `4h`… |
| `poll_interval_sec` | как часто бот проверяет рынок и стопы |
| `strategy.name` | `voting` или `mean_reversion` |
| `strategy.params` | параметры стратегии (пусто — значения по умолчанию, см. [раздел 6](#6-стратегии)) |
| `risk.*` | риск-менеджмент (см. [раздел 7](#7-риск-менеджмент)) |
| `fees.taker`, `fees.slippage` | комиссия и проскальзывание для paper и бэктеста |
| `paper.initial_balance` | виртуальный стартовый баланс |
| `live.exchange_stop_loss` | на фьючерсах дублировать стоп-лосс ордером на бирже |
| `live.i_understand_the_risks` | предохранитель: без `true` режим `live` не запустится |

**Пример для фьючерсов:**

```yaml
mode: paper
exchange:
  name: bingx
  market_type: swap
symbols: [BTC/USDT:USDT, ETH/USDT:USDT]
timeframe: 15m
strategy:
  name: voting
risk:
  leverage: 2
  allow_short: true
```

На споте бот торгует только в лонг и без плеча: настройки `leverage` и `allow_short` там игнорируются.

## 4. Порядок запуска: бэктест → paper → live

### Шаг 1. Бэктест

Бот скачивает историю с BingX и прогоняет стратегию:

```bash
python -m bot backtest                                     # все пары из config.yaml, 180 дней
python -m bot backtest --symbol BTC/USDT --days 365
python -m bot backtest --strategy mean_reversion --timeframe 1h
python -m bot backtest --csv data/my_candles.csv --symbol BTC/USDT   # свои данные
python -m bot backtest --save-data                         # сохранить скачанные свечи в data/
```

**Пример отчёта:**

```
===== Бэктест BTC/USDT =====
  Доходность, %            5.21
  Купить и держать, %      105.2
  Макс. просадка, %        -2.58
  Коэф. Шарпа (год.)       3.81
  Сделок                   78
  Прибыльных сделок, %     44.9
  Profit factor            1.36
```

Сделки, кривая капитала и график (если установлен `matplotlib`) сохраняются в папку `backtest_results/`.

**Как читать отчёт:**

- **Profit factor > 1.3** — стратегия заработала заметно больше, чем потеряла.
- **Макс. просадка** — насколько капитал проседал от пика. Готовы ли вы к такой просадке с реальными деньгами?
- Сравните доходность с **«Купить и держать»**.
- Проверьте стратегию на разных периодах и парах. Если она прибыльна только на одном отрезке, скорее всего, это подгонка.

Чтобы бэктест был честным, бот не заглядывает в будущее: сигнал считается по закрытию свечи, а сделка исполняется по открытию следующей. Комиссия и проскальзывание учитываются.

### Шаг 2. Paper trading

В `config.yaml` укажите `mode: paper` и запустите:

```bash
python -m bot run
```

Бот работает на реальных ценах в реальном времени, но ордера не отправляет: исполнение симулируется с комиссией и проскальзыванием. Дайте ему поработать **хотя бы 1–2 недели**. Результаты смотрите командой `python -m bot status`.

### Шаг 3. Реальная торговля

1. Пропишите API-ключи в `.env` (см. [раздел 2](#2-api-ключи-bingx)).
2. Проверьте подключение:

   ```bash
   python -m bot check
   ```

   Команда покажет цены, минимальные размеры ордеров и баланс. Если ключи неверные, вы увидите ошибку авторизации.
3. В `config.yaml` поставьте `mode: live` и `live.i_understand_the_risks: true`.
4. Начните с **маленькой суммы** на счёте.
5. Запустите:

   ```bash
   python -m bot run
   ```

**Чем живой режим отличается от paper:**

- Бот ставит **рыночные** ордера.
- На фьючерсах при старте бот сам определяет режим позиций (one-way или hedge) и выставляет плечо `risk.leverage` по каждой паре.
- Если `live.exchange_stop_loss: true`, вместе с ордером входа на бирже ставится стоп-лосс. Позиция защищена, даже если бот или сервер упадёт.
- На каждом цикле бот сверяет позиции с биржей. Если позицию закрыл биржевой стоп или вы закрыли её вручную, бот это заметит и уберёт позицию из учёта.

> Бот ведёт **только свои позиции**. Не торгуйте вручную теми же парами на том же счёте: при закрытии фьючерсной позиции бот отменяет все открытые ордера по этой паре. Лучше создать для бота отдельный субаккаунт BingX.

**Остановка бота:** нажмите `Ctrl+C`. Открытые позиции **не закрываются**: они сохраняются в `state/state.json`, и при следующем запуске бот продолжит их вести. Чтобы закрыть всё по рынку, выполните:

```bash
python -m bot close-all
```

## 5. Команды

```
python -m bot run                 запустить торговлю (режим из config.yaml)
python -m bot backtest [опции]    бэктест (--symbol, --timeframe, --days, --strategy, --csv, --balance)
python -m bot check               проверить конфиг, связь с биржей, ключи и Telegram
python -m bot status [--last N]   открытые позиции, статистика и последние сделки

```

Общие опции:

- `-c путь/к/config.yaml` — другой файл конфигурации. Так можно запустить несколько ботов с разными настройками: у каждого должны быть свои пути в `storage`.
- `-v` — подробный лог.

## 6. Стратегии

Все стратегии принимают решения **по закрытию свечи**. Один и тот же код используется в бэктесте, в paper и в live, поэтому бэктест отражает реальное поведение бота.

### `mean_reversion` — возврат к среднему

**Идея:** во флэте цена, далеко ушедшая от средней, обычно возвращается к ней.

- **Вход в лонг:** закрытие ниже нижней полосы Боллинджера **и** RSI < `rsi_oversold` **и** ADX < `max_adx` (нет сильного тренда).
- **Выход из лонга:** цена дошла до средней линии Боллинджера **или** RSI > `rsi_exit_long`.
- **Шорт** (только на фьючерсах) — зеркально: выше верхней полосы и RSI > `rsi_overbought`.

| Параметр | По умолчанию | Описание |
|---|---|---|
| `bb_period` / `bb_std` | 20 / 2.0 | период и ширина полос Боллинджера |
| `rsi_period` | 14 | период RSI |
| `rsi_oversold` / `rsi_overbought` | 30 / 70 | уровни перепроданности и перекупленности |
| `rsi_exit_long` / `rsi_exit_short` | 60 / 40 | RSI для выхода |
| `max_adx` | 30 | фильтр тренда (0 — выключить) |

Лучше всего работает на боковом рынке. В сильном тренде фильтр ADX блокирует входы.

### `voting` — голосование индикаторов

Каждый индикатор голосует «за рост» (+1), «за падение» (−1) или «нейтрально» (0):

| Голос | Условие +1 / −1 | Вес |
|---|---|---|
| `trend` | EMA(12) выше / ниже EMA(26) | 1.0 |
| `long_trend` | цена выше / ниже EMA(200) | 1.0 |
| `macd` | гистограмма MACD > 0 / < 0 | 1.0 |
| `rsi` | RSI > 55 / < 45 | 1.0 |
| `bollinger` | цена ниже нижней / выше верхней полосы | 0.5 |
| `volume` | OBV выше / ниже своей EMA(20) | 0.5 |

Итог `score` — взвешенная сумма голосов, нормированная в диапазон от −1 до +1.

- **Вход в лонг:** `score` пересекает вверх `entry_threshold` (по умолчанию 0.6). Это значит, что большинство индикаторов согласны.
- **Выход из лонга:** `score` < `exit_threshold` (по умолчанию 0).
- **Шорт** — зеркально.

Пример настройки:

```yaml
strategy:
  name: voting
  params:
    entry_threshold: 0.7      # строже — меньше сделок, выше качество
    exit_threshold: 0.1
    weights: {volume: 0, bollinger: 1}   # отключить OBV, усилить Bollinger
```

Свою стратегию можно добавить так:

1. Создайте файл в `bot/strategies/` с классом-наследником `Strategy`.
2. Реализуйте в нём `warmup` и `_signals()`: они должны выставлять колонки `enter_long`, `exit_long`, `enter_short`, `exit_short`.
3. Зарегистрируйте класс в `bot/strategies/__init__.py`.

## 7. Риск-менеджмент

| Параметр | По умолчанию | Описание |
|---|---|---|
| `risk_per_trade` | 0.01 | сколько капитала теряется, если сработает стоп (1%) |
| `max_position_pct` | 0.25 | максимум капитала (маржи) в одной позиции |
| `max_open_positions` | 2 | максимум одновременно открытых позиций |
| `stop_loss_atr` | 2.0 | стоп-лосс = цена входа ∓ 2×ATR |
| `take_profit_atr` | 3.0 | тейк-профит = цена входа ± 3×ATR (`null` — выключить) |
| `trailing_stop_atr` | null | трейлинг-стоп на расстоянии N×ATR от лучшей цены |
| `max_daily_loss_pct` | 0.05 | при дневном убытке > 5% новые сделки не открываются до 00:00 UTC |
| `cooldown_bars` | 2 | пауза в свечах после закрытия сделки по паре |
| `leverage` | 2 | плечо (только фьючерсы) |
| `allow_short` | true | разрешить шорты (только фьючерсы) |

**Как считается размер позиции:**

```
объём = (капитал × risk_per_trade) / (ATR × stop_loss_atr)
```

Затем объём ограничивается сверху долей `max_position_pct` (с учётом плеча) и свободным балансом. Если объём получился меньше минимального ордера биржи, сделка пропускается. Пример: при капитале 1000 USDT и риске 1% сработавший стоп обойдётся примерно в 10 USDT плюс комиссия. Гэп цены может увеличить потерю.

Плечо **не увеличивает риск на сделку**: его ограничивает стоп-лосс. Плечо лишь уменьшает требуемую маржу. Ставить плечо выше 3–5 не рекомендуется.

## 8. Telegram-уведомления

1. В Telegram напишите **@BotFather**, отправьте `/newbot` и получите **токен**.
2. Напишите своему новому боту любое сообщение.
3. Откройте в браузере `https://api.telegram.org/bot<ТОКЕН>/getUpdates` и найдите `"chat":{"id":123456789}`. Это ваш **chat_id**.
4. Впишите оба значения в `.env`:

   ```
   TELEGRAM_BOT_TOKEN=123456:ABC...
   TELEGRAM_CHAT_ID=123456789
   ```

5. В `config.yaml` поставьте `telegram.enabled: true`.
6. Проверьте связь: `python -m bot check` пришлёт тестовое сообщение.

**Какие приходят уведомления:**

- запуск и остановка бота;
- открытие позиции: цена, объём, SL и TP;
- закрытие позиции: причина и PnL;
- итог дня;
- ошибки (если `notify_errors: true`).

В режиме paper сообщения помечены `[PAPER]`.

## 9. Работа 24/7 на сервере

Боту нужен постоянно включённый компьютер. Удобнее всего VPS с Linux. Не забудьте добавить IP сервера в белый список API-ключа.

**Самый простой способ — `tmux`:**

```bash
tmux new -s bot
source .venv/bin/activate && python -m bot run
# Ctrl+B, затем D — отключиться; tmux attach -t bot — вернуться
```

**Надёжнее — systemd** (автозапуск и перезапуск при сбое). Создайте файл `/etc/systemd/system/trading-bot.service`:

```ini
[Unit]
Description=BingX trading bot
After=network-online.target

[Service]
WorkingDirectory=/home/USER/trading-bot
ExecStart=/home/USER/trading-bot/.venv/bin/python -m bot run
Restart=always
RestartSec=30
User=USER

[Install]
WantedBy=multi-user.target
```

Затем включите сервис и смотрите лог:

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now trading-bot
journalctl -u trading-bot -f      # лог в реальном времени
```

Лог также пишется в файл `logs/bot.log`.

## 10. Файлы и структура проекта

```
bot/
  __main__.py          команды CLI
  config.py            загрузка и проверка config.yaml и .env
  indicators.py        индикаторы: EMA, SMA, RSI, Bollinger, ATR, MACD, ADX, OBV
  strategies/          стратегии: base, mean_reversion, voting
  risk.py              размер позиции, стоп-лосс, тейк-профит, трейлинг
  exchange.py          BingX через ccxt: LiveBroker (реальные ордера), PaperBroker (симуляция)
  trader.py            основной торговый цикл
  backtest.py          бэктест и метрики
  state.py             сохранение состояния и журнал сделок
  notifier.py          Telegram
tests/                 автотесты (pytest), работают без сети
config.example.yaml    пример конфигурации
.env.example           пример файла с ключами
```

Файлы, которые бот создаёт во время работы (в git не попадают):

- `state/state.json` — открытые позиции, виртуальный баланс paper и служебные данные. **Не удаляйте этот файл, пока есть открытые позиции.** При смене режима paper ↔ live используйте другой путь `storage.state_file` или удалите файл, когда позиций нет.
- `state/trades.csv` — журнал всех закрытых сделок.
- `logs/bot.log` — лог.
- `backtest_results/` — результаты бэктестов.

## 11. Частые проблемы

| Проблема | Решение |
|---|---|
| `Нет связи с биржей` | Проверьте интернет. BingX может быть недоступен в вашей стране или у хостера — попробуйте другой сервер. |
| `Ошибка авторизации` | Проверьте ключ и секрет в `.env`, права ключа и белый список IP. |
| `Для swap пары пишутся как BTC/USDT:USDT` | На фьючерсах используйте формат `BTC/USDT:USDT`. |
| `размер позиции ниже минимального ордера` | Слишком маленький депозит или риск. Увеличьте баланс, `risk_per_trade` или `max_position_pct`. |
| Бот долго не торгует | Это нормально: стратегии ждут подходящих условий. Увидеть текущие RSI и score можно в логе. Для частых сделок уменьшите таймфрейм или ослабьте пороги (сначала проверьте их в бэктесте). |
| `Режим live заблокирован` | Поставьте `live.i_understand_the_risks: true`. |
| `Не удалось установить плечо` | Закройте открытые позиции по паре вручную и перезапустите бота. |

## 12. Ограничения

- Бэктест не учитывает funding (ставку финансирования) на фьючерсах, ликвидацию и минимальный размер ордера.
- Стоп-лосс и тейк-профит проверяются раз в `poll_interval_sec` по последней цене. При резких движениях исполнение может быть хуже уровня. На фьючерсах от этого страхует биржевой стоп-лосс (`exchange_stop_loss`).
- На споте нет биржевого стоп-ордера: если бот выключен, стоп не сработает.
- Бэктест нескольких пар считает каждую пару отдельно, с полным стартовым балансом.
- Прошлые результаты не гарантируют будущих.
